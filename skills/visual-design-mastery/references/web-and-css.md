# Web & CSS — the browser as canvas

The browser in 2026 is the most powerful design tool most developers never fully open. The default web looks the way it does — safe, centered, forgettable — not because the platform is limited but because people reach for the same twelve Tailwind utilities and stop. This file is about refusing that. Every choice — a neutral's hue, a heading's line-break, a shadow's number of layers, whether a grid is symmetric — is load-bearing. Beautiful web work is not decoration bolted onto a layout; it is a coherent system of type, color, space, and depth where the browser does the heavy lifting through modern CSS, and JavaScript is reserved for the two or three interactions that actually earn it. Ship intention, not defaults.

---

## The AI-slop web look — avoid on sight

If your page has these, you built the same page everyone else did. Name them, then don't:

- **Everything centered.** `text-align: center` and `mx-auto` from hero to footer. Centered text is for ≤2 lines. Long-form and UI want a left edge the eye can return to.
- **The one purple gradient hero.** `from-purple-500 to-indigo-500`, 45°, on repeat. A gradient can be beautiful; *this specific* one is a tell.
- **Inter everywhere, one weight.** Inter (or the system stack) at 400/600 for headings and body alike. Competent and completely anonymous.
- **`rounded-2xl` on every surface.** One radius on cards, buttons, inputs, avatars, the whole page. Radius is a hierarchy signal — vary it or drop it.
- **Lone neon accent on near-black.** `#0a0a0a` background, one electric cyan/lime that glows on everything. Dark ≠ `#0a0a0a`; one accent ≠ a palette.
- **Emoji as section markers.** 🚀 features, ✨ benefits, 🎯 mission. Reads as a pitch deck, never as design.
- **Pure-grey neutrals.** `#888`, `#ccc`, `#333` — dead greys with zero hue. Real neutrals lean warm or cool.
- **Uniform `shadow-xl` on everything** — one heavy blurry black shadow, same on the button and the modal. Flattens all depth into one plane.
- **The 3-up icon-title-blurb card grid**, three identical cards, and **gradient-clipped heading text** as the *only* idea in the design.

The through-line: no decisions were made. Every fix below is a decision.

## Color — considered, not picked from a swatch

**Work in OKLCH.** It's perceptually uniform: equal lightness *looks* equal across hues, so a scale generated by stepping `L` actually reads as even. `oklch(L C H)` — L 0–1, C chroma ~0–0.4, H 0–360.

**Neutrals get a hue bias — never pure grey.** Push a little chroma at a consistent hue through the whole grey ramp. Warm ink (H≈70) feels editorial/organic; cool slate (H≈260) feels technical/precise. Pick one and commit.

```css
:root {
  /* cool-slate neutrals: real hue, tiny chroma, even L steps */
  --n-50:  oklch(0.985 0.004 260);
  --n-100: oklch(0.96  0.006 260);
  --n-300: oklch(0.87  0.012 260);
  --n-500: oklch(0.64  0.018 260);
  --n-700: oklch(0.44  0.020 260);
  --n-900: oklch(0.24  0.022 260);
  --n-950: oklch(0.16  0.022 260);

  --accent:  oklch(0.68 0.17 30);   /* one confident hue */
  --accent-2: oklch(0.72 0.13 200); /* a supporting cool, used sparingly */
}
```

**Semantic tokens over raw values.** Components reference roles, not colors. This is also how dark mode stays a one-block override instead of a per-component rewrite.

```css
:root {
  --surface: var(--n-50);
  --surface-raised: white;
  --text: var(--n-900);
  --text-muted: var(--n-500);
  --border: var(--n-300);
}
/* Explicit toggle wins in both directions, regardless of OS. */
:root[data-theme="dark"] {
  --surface: var(--n-950);
  --surface-raised: var(--n-900);
  --text: var(--n-100);
  --text-muted: var(--n-500);
  --border: oklch(1 0 0 / 0.10); /* hairline as translucent white, not a grey */
}
/* Auto: follow the OS unless the user explicitly chose light. */
@media (prefers-color-scheme: dark) {
  :root:not([data-theme="light"]) {
    --surface: var(--n-950);
    --surface-raised: var(--n-900);
    --text: var(--n-100);
    --text-muted: var(--n-500);
    --border: oklch(1 0 0 / 0.10);
  }
}
```

**Derive tints, don't hand-pick them.** `color-mix()` and relative color syntax generate hovers, tints, and rings from one source, so the palette stays coherent:

```css
background: color-mix(in oklch, var(--accent) 12%, var(--surface)); /* accent wash */
border-color: oklch(from var(--accent) l c h / 0.35);               /* accent at 35% alpha */
--accent-hover: oklch(from var(--accent) calc(l - 0.06) c h);        /* darker on press */
```

**Contrast is non-negotiable.** Body text ≥ 4.5:1, large/UI text ≥ 3:1 against its actual background. Bright saturated accents rarely pass as text on light surfaces — reserve them for fills and use a darkened variant for accent-colored text. Verify with a checker; don't eyeball.

## Typography — the highest-leverage craft on the page

**Pair a characterful display face with a clean text face.** The tension is the point. All free (Google Fonts / Fontshare):

- **Fraunces** (display; optical + `SOFT`/`WONK` axes) + **Satoshi** or **IBM Plex Sans** (text)
- **Instrument Serif** (display) + **Geist** (text) — modern editorial
- **Bricolage Grotesque** (display) + **Newsreader** (serif text, has `opsz`) — literary
- **Clash Display** (display) + **General Sans** (text) — both Fontshare, contemporary

Never both faces from the same family, and never Inter-on-Inter.

**Use a modular scale with a real ratio** — don't type arbitrary sizes. 1.25 (major third) for UI; 1.333 (perfect fourth) for editorial contrast. From a 1rem base at 1.25: 0.8 / 1 / 1.25 / 1.563 / 1.953 / 2.441rem.

**Fluid type and space with `clamp()`** — no breakpoint jumps. Pattern: `clamp(min, preferred-with-vw, max)`.

```css
--step-0: clamp(1rem, 0.93rem + 0.35vw, 1.19rem);   /* body */
--step-2: clamp(1.56rem, 1.3rem + 1.3vw, 2.44rem);  /* h2 */
--space-l: clamp(2rem, 1.2rem + 4vw, 4rem);          /* section rhythm */
```

**Measure ~65ch.** Body copy at `max-width: 65ch` (comfortable 45–75). This one line fixes most "walls of text."

**`text-wrap` — free typesetting.** `balance` for headings (evens line lengths, best ≤~6 lines), `pretty` for body (kills orphans/rivers). `balance` is Baseline; `pretty` is Chromium+Safari, no Firefox yet as of early 2026 — it degrades harmlessly to normal wrapping.

```css
h1, h2, h3 { text-wrap: balance; }
p, li { text-wrap: pretty; }
```

**Variable fonts + optical sizing.** One file, every weight; let `opsz` tune letterforms to size automatically.

```css
h1 { font-weight: 620; font-optical-sizing: auto; }   /* opsz follows font-size automatically */
/* font-variation-settings is the low-level override, applied last: pinning "opsz" there DEFEATS
   optical sizing, and "wght" there bypasses font-weight. Use it only for axes with no high-level
   property — Fraunces' "SOFT" and "WONK", Anybody's width beyond font-stretch. */
```

**Tracking is not one value.** Large display text wants slight *negative* tracking; all-caps labels want *positive* tracking or they look cramped:

```css
.display { letter-spacing: -0.02em; }
.eyebrow { text-transform: uppercase; letter-spacing: 0.08em; font-size: 0.75rem; }
```

**Inline a critical webfont as a data URI** to kill the FOUT/FOIT flash on the first paint (LCP text). Subset first (`glyphhanger` / `fonttools`) so it stays small, then base64 the woff2:

```css
@font-face {
  font-family: "Display";
  src: url(data:font/woff2;base64,d09GMgABAAAA…) format("woff2");
  font-weight: 400 700; font-display: swap;
}
```

Inline only the one or two faces above the fold; link the rest.

## Layout with intent

**Grid is a design tool, not a table.** Design on an explicit named grid and place things deliberately. Asymmetry beats a centered column.

```css
.editorial {
  display: grid;
  grid-template-columns: [full-start] minmax(1rem,1fr) [main-start] repeat(12, minmax(0,5.5rem)) [main-end] minmax(1rem,1fr) [full-end];
  column-gap: 1.5rem;
}
.lede    { grid-column: main-start / span 7; }   /* text on the left */
.figure  { grid-column: 8 / full-end; }          /* image bleeds off the right edge */
```

**Broken-grid / editorial look:** let one element break the container (bleed to `full-end`), overlap two items with negative margin or grid-cell stacking, and offset a caption into the margin. Deliberate imbalance reads as design; perfect symmetry reads as a template.

**Negative space is a material.** Generous, *uneven* whitespace — more above a section than below, asymmetric padding — creates hierarchy for free. Cramped + uniform is the slop signature.

**Layered shadow system for z-depth.** One shadow is flat. Stack 2–3 (tight+soft+ambient) and tint them with the surface hue, never pure black:

```css
--shadow-1: 0 1px 2px oklch(0.2 0.02 260 / .06);
--shadow-3: 0 1px 2px oklch(0.2 0.02 260 / .05),
            0 4px 8px oklch(0.2 0.02 260 / .06),
            0 12px 24px oklch(0.2 0.02 260 / .08);
```

Map elevation to a token (`--shadow-1` chips, `--shadow-3` popovers, more for modals) so depth is a system, not a guess.

## Modern CSS most code ignores

**Container queries** — components that respond to *their slot*, not the viewport. This is how one card component works in a sidebar and a full-width grid.

```css
.card-host { container-type: inline-size; container-name: card; }
@container card (min-width: 28rem) {
  .card { grid-template-columns: 8rem 1fr; }  /* go horizontal when the slot is wide */
}
.card h3 { font-size: clamp(1rem, 4cqi, 1.5rem); } /* cqi = 1% of container inline size */
```

**`:has()` — the parent/sibling selector.** Style a parent from its children, no JS:

```css
.card:has(img) { grid-template-rows: auto 1fr; }
label:has(+ input:required)::after { content: " *"; color: var(--accent); }
:root:has(dialog[open]) { overflow: hidden; }           /* scroll-lock behind a modal */
.field:has(input:invalid:not(:placeholder-shown)) { --border: oklch(0.6 0.2 25); }
```

**Subgrid** — align inner elements across sibling cards to shared tracks, so every card's title/body/footer line up even with uneven content:

```css
.row { display: grid; grid-template-columns: repeat(3,1fr); }
.card { display: grid; grid-row: span 3; grid-template-rows: subgrid; }
```

**`@property`** — typed custom properties that *animate* (plain custom props can't be interpolated). Essential for the border-glow below and for gradient-angle motion:

```css
@property --angle { syntax: "<angle>"; inherits: false; initial-value: 0deg; }
```

**`backdrop-filter` — real glass, done right.** Blur + a *saturation* boost, over a translucent fill, with a hairline highlight border. The saturation is what separates convincing glass from muddy frost:

```css
.glass {
  background: oklch(1 0 0 / 0.06);
  backdrop-filter: blur(14px) saturate(1.6);
  border: 1px solid oklch(1 0 0 / 0.12);
}
```

Use sparingly and only where there's contrast behind it — glass on a flat background is just a grey box.

**Cascade layers** — end specificity wars without `!important`. Declare order once; later layers always win regardless of selector strength:

```css
@layer reset, base, tokens, components, utilities;
```

**Anchor positioning** — tether tooltips/menus/popovers to a trigger in pure CSS, no positioning library. Chrome/Edge 125+ (`position-try-fallbacks` from 128; 125–127 spelled it `position-try-options`), Safari 26+, Firefox 147+ (January 2026) — Baseline "newly available" in 2026, so gate with `@supports (anchor-name: none)` and keep a base position for the tail of older browsers.

```css
.btn { anchor-name: --btn; }
.menu {
  position: absolute; position-anchor: --btn;
  top: anchor(bottom); justify-self: anchor-center; margin-top: 0.5rem;
}
@position-try --flip-up { bottom: anchor(top); top: auto; margin-bottom: 0.5rem; }
.menu { position-try-fallbacks: --flip-up; }  /* flips when it would clip */
```

**Scroll-driven animations** — scroll-linked reveals/progress with zero JS and no scroll listeners; they run off the compositor. Chrome/Edge 115+, Safari 26+ (landed Sept 2025); Firefox behind a flag in early 2026, so gate behind `@supports` and always respect reduced motion (deeper timing craft lives in `motion-and-animation.md`):

```css
@supports (animation-timeline: view()) {
  @media (prefers-reduced-motion: no-preference) {
    .reveal {
      animation: reveal linear both;
      animation-timeline: view();
      animation-range: entry 0% cover 35%;
    }
    @keyframes reveal { from { opacity: 0; translate: 0 2rem; } }
  }
}
```

**View Transitions** — morph between DOM states/pages. Same-document: `document.startViewTransition(() => updateDOM())`. Cross-document, no framework:

```css
@view-transition { navigation: auto; }
.hero-img { view-transition-name: hero; } /* same name on both pages → it flies across */
```

Keep the transition *itself* short and eased — see the motion sibling; don't re-derive easing here.

## Micro-interactions and detail

**`:focus-visible`, never a killed outline.** Keyboard users get a clear ring; mouse clicks don't. A thick offset ring in the accent looks intentional:

```css
:focus-visible { outline: 2px solid var(--accent); outline-offset: 3px; border-radius: 3px; }
```

**Hover/active with real transitions.** Transition specific properties (not `all`), move a hair, and give a distinct pressed state. Keep it fast — timing/easing detail is the motion sibling's job:

```css
.btn { transition: background-color .15s, transform .12s, box-shadow .15s; }
.btn:hover  { background: var(--accent-hover); box-shadow: var(--shadow-1); }
.btn:active { transform: translateY(1px) scale(0.99); }
```

**Cursor-tracked border-glow** (the Linear/Aceternity spotlight edge). A radial gradient follows the pointer, masked to a 1px border via `mask-composite`. JS only writes two custom props:

```css
.glow { position: relative; border-radius: 14px; }
.glow::before {
  content: ""; position: absolute; inset: 0; border-radius: inherit; padding: 1px;
  background: radial-gradient(180px circle at var(--mx) var(--my),
                              oklch(0.72 0.18 265), transparent 65%);
  -webkit-mask: linear-gradient(#000 0 0) content-box, linear-gradient(#000 0 0);
  -webkit-mask-composite: xor; mask-composite: exclude;  /* border only */
  opacity: 0; transition: opacity .2s;
}
.glow:hover::before { opacity: 1; }
```
```js
card.addEventListener("pointermove", e => {
  const r = card.getBoundingClientRect();
  card.style.setProperty("--mx", `${e.clientX - r.left}px`);
  card.style.setProperty("--my", `${e.clientY - r.top}px`);
});
```

**Scroll reveals** should prefer the pure-CSS `view()` timeline above over `IntersectionObserver` — less JS, no jank, and reduced-motion handling one `@media` wrapper away (as above — the timeline itself does not consult the preference).

## Reference libraries — inspiration to hand-implement, not crutches

Read their source, lift the *technique* and the math, then rebuild it with **your** tokens. Do not ship twenty dependencies for two effects.

- **21st.dev** — shadcn-compatible component marketplace; search a pattern, then re-tokenize it to your palette rather than pasting defaults.
- **Magic UI**, **Aceternity UI**, **React Bits** — animated components (spotlight cards, marquees, animated backgrounds/text). Study the CSS/JS, reimplement the one you need.
- **KokonutUI** — Tailwind/React component set. **Bklit** — data-viz/chart components when you need charts that aren't ugly.
- **Motion** (`motion.dev`, npm `motion`; `motion/react` for React) — hybrid JS+native engine; the default JS animation lib. **anime.js v4** (`import { animate, createTimeline } from "animejs"`) for timeline-heavy or non-React work. Timing/easing guidance: `motion-and-animation.md`.
- **Refero** (`styles.refero.design`) and **Godly** (`godly.design`) — galleries of real shipped product UI. Mine them for structure, spacing rhythm, and type pairings; steal the *reasoning*, never pixel-copy a screen.

React-specific component systems are covered in the sibling React file — mention them, but the browser doesn't need a framework to be beautiful.
