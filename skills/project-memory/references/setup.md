# First-run setup

Run once, in the project root, the first time there is something real to record. The schemas
themselves are in `SKILL.md` — this file only bootstraps the files and shows what a healthy
`INDEX.md` looks like.

## Bootstrap

```sh
mkdir -p .claude/memory/decisions
cp "$SKILLS/project-memory/references/build-index.mjs" .claude/memory/

printf -- '---\nkind: questions\nupdated: %s\n---\n\n' "$(date +%F)" > .claude/memory/questions.md
printf -- '---\nkind: backlog\nupdated: %s\n---\n\n'   "$(date +%F)" > .claude/memory/backlog.md
printf -- '---\nkind: facts\nupdated: %s\n---\n\n'     "$(date +%F)" > .claude/memory/facts.md

node .claude/memory/build-index.mjs
```

`$SKILLS` is wherever this skill lives (`~/.claude/skills` or the global-config checkout).
PowerShell equivalent: `New-Item -ItemType Directory -Force .claude/memory/decisions`, then
`Set-Content -Encoding utf8` for each stub.

Then commit it. `.claude/memory/` is repo content, not local scratch — the point is that the
next person and the next session both get it.

Do not seed the files with example entries. An empty store that fills from real work is trusted;
a pre-populated one teaches everyone that the contents are decorative.

## Adding a decision

```sh
N=$(printf '%04d' $(( $(ls .claude/memory/decisions | wc -l) + 1 )))
$EDITOR ".claude/memory/decisions/${N}-advisory-locks-for-job-claiming.md"
node .claude/memory/build-index.mjs
```

The number is monotonic and never reused, including for reversed decisions — ids are cited from
other files and from git history, so reusing one silently rewrites the past. Gaps are fine.

## What a healthy INDEX.md looks like

Generated output, for calibration. If yours is much longer than this, the store has stopped
paying for itself — prune before adding.

```markdown
<!-- GENERATED by build-index.mjs — do not edit. Run: node .claude/memory/build-index.mjs -->
# Project memory

Newest entry 2026-09-01 · 1 live decision(s) (+1 superseded/reversed) · 1 open question(s) · 2 open backlog item(s), 1 blocked

Read this file first. Open the individual files only when a line below is relevant to the work
at hand. Durable project facts: [facts.md](facts.md).

## Open questions
- `Q004` Does the billing webhook fire twice? — blocks `B012`; Stripe event log

## Backlog — open
- `B012` Wire the retry budget into the worker — `src/worker/retry.ts` (blocked: `Q004`)
- `B013` Backfill `claimed_at` — `migrations/`

## Decisions
| id | date | status | title | verify |
|---|---|---|---|---|
| `D0007` | 2026-08-14 | accepted | [Postgres advisory locks for job claiming](decisions/0007-postgres-advisory-locks.md) | `src/jobs/claim.ts` |
| `D0003` | 2026-05-02 | superseded | [Redis queue for background jobs](decisions/0003-redis-queue.md) | `src/queue/redis.ts` |
```

Three properties of that output worth keeping if you ever rewrite the generator:

- **Superseded decisions stay listed.** They are how you avoid re-proposing what was already
  rejected — the single most valuable thing in the store.
- **The freshness stamp is derived from the data**, never from `Date.now()`. A generated
  timestamp changes on every run, churns the git diff, and trains everyone to ignore the file.
- **Only unchecked items are indexed.** Done work stays in `backlog.md` for the record but does
  not consume space in the file that gets read every session.

## Pruning

When `INDEX.md` outgrows one comfortable read:

1. Delete backlog items checked off before the last release — git has them.
2. Close or delete questions open longer than a couple of months. An unanswerable question is
   dead; a stale open-question list is why people stop reading the index.
3. Merge facts that turned out to be the same fact.
4. Leave decisions alone. They are the append-only part, and the archive is the point.
